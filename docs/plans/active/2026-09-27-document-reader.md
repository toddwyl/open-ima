# 文档阅读器规划（引用卡片内直接阅读来源全文）

- 状态：规划中（暂不实施，2026-09-27 由用户明确推迟）
- 触发背景：问答引用卡片目前只能「在文档列表中查看」定位到文件行；用户希望在卡片内直接预览/阅读文件全文，减少来回跳转。

## 目标

1. 从引用卡片可直接打开对应文档的阅读视图，看到全文而非仅片段。
2. 阅读视图能定位到被引用的片段位置并高亮（按 chunk 定位）。
3. 文档页（DocumentsView）的文件行也可打开同一阅读器。

## 待调研的关键问题

1. **正文从哪来**：解析后的全文是否已持久化？目前 chunks 表只有切片内容，documents 表可能不含全文；parser sidecar 解析后是否保留了全文文件（`parser/` 输出目录？）需要确认。若未落库，需要新增存储（如 `documents.content_path` 指向解析产物，或全文入库）。
2. **后端接口形态**：大概率新增 `GET /api/documents/{document_biz_id}/content`，返回正文 + chunk 偏移列表（chunk_biz_id → 起止位置），供前端高亮定位。
3. **格式策略**：首版只做纯文本 / Markdown / HTML 转文本的预览；PDF/DOCX 原文渲染（版式还原）明确不在范围内。

## 范围

- 前端：阅读器面板（侧边抽屉或全屏覆盖层），引用卡片加「阅读全文」入口，片段高亮 + 滚动定位。
- 后端：文档正文读取接口（含权限/范围校验：仅当前知识库内文档）。
- 测试：接口往返测试 + 前端打开/定位/高亮的回归测试。

## 非目标

- 不做版式级 PDF/DOCX 渲染，不引入重型查看器依赖。
- 不改动现有引用检索与排序逻辑。
